User Guide

TalentLink is a desktop application that HR recruiters in recruitment agencies use to manage their contacts, optimized for use through a Command Line Interface (CLI) while retaining the benefits of a Graphical User Interface (GUI). If you type quickly, TalentLink can help you manage your jobseeker/client contacts faster than traditional GUI applications. Additionally, TalentLink also provides support for many tasks that recruiters often do on a daily basis, such as recording notes on various jobseekers/clients, searching for jobseekers with particular educational qualifications and determine which jobseekers to link up with each client’s job opening.

Features

Notes about the command format:

  • Words inside angle bracket <field name> are the parameters to be supplied by the user, hereby called fields.

    Field values can contain spaces, but preceding and trailing spaces are ignored.

    For example, in addj n/<name>, replace <name> with a value such as John Doe.

  • Fields in square brackets are optional. Every other items are required.

    For example, n/<name> [t/<tag>] can be written as n/John Doe t/friend or as n/John Doe.

  • Items followed by ... can appear more than once. Every other items must only appear once.

    For example, [t/<tag>]... may be omitted, or written as t/friend or t/friend t/family.

  • Prefixed parameters can be in any order.

    For example, if the command specifies n/<name> p/<phone number>, p/<phone number> n/<name> is also acceptable.

    For editj, editc, tagj, tagc, untagj, and untagc, the index must come first, followed by the fields or tags to update.

  • Extraneous parameters for commands that take no parameters, such as help, exit, list, listj, listc, clearj, and clearc, are ignored.

    For example, help 123 is interpreted as help.

  • If you are using a PDF version of this document, be careful when copying and pasting commands that span multiple lines as space characters surrounding line-breaks may be omitted when copied over to the application.

Adding and modifying contacts

Common info about contacts

Jobseeker contacts contains the following values, and their corresponding constraints:

  • Name
    • can contain any characters except / (e.g. Beyoncé and Zoë are allowed)
    • must not be blank
  • Phone number
    • contains only digits
    • must be at least 3 digits long
  • Email address
    • must follow the conventional format of email address
  • Physical address
    • can be any value other than empty
  • Remarks about the individual
    • can be any value
  • Tags
    • can have multiple unique tags
    • See Managing tags for more details about tags.

Client contacts contains the following values, and their corresponding constraints:

  • Name
    • can contain any characters except / (e.g. Ben & Jerry's, Pokémon and 7-Eleven are allowed)
    • must not be blank
  • Phone number
    • contains only digits
    • must be at least 3 digits long
  • Email address
    • must follow the conventional format of email address
  • Physical address
    • can be any value other than empty
  • Remarks about the individual
    • can be any value
  • Tags
    • can have multiple unique tags
    • See Managing tags for more details about tags.

Contacts are identified by their phone number and their email address.

The q/ field is only accepted by addj and editj; j/ is only accepted by addc and editc. Using either field with the wrong contact type is rejected, even when its value is empty.

  • Contacts with the same phone number and email address are treated as the same contacts, even if their other fields differs.

  • If contacts only have either the same phone number or email address, they are treated as different contacts.

Adding a jobseeker: addj

Adds a jobseeker to TalentLink.

Adding duplicate jobseeker contacts is not allowed. However, adding an existing client contact to the jobseeker list is allowed

Format: addj n/<name> p/<phone number> e/<email> a/<address> [q/<highest qualification>] [r/<remarks>] [t/<tag> [<more tags>]...]

  • <name>: the name of the jobseeker
  • <phone number>: the phone number of the jobseeker
  • <email>: the email address of the jobseeker
  • <address>: the address of the jobseeker
  • <highest qualification>: the jobseeker’s highest qualification, e.g. Diploma in IT
    • Optional free text. Omit q/ to leave it empty; specify it at most once.
  • <remarks>: your remarks about this jobseeker
    • Optional. When omitted, the remarks value is treated as empty.
  • <tag>: a tag for this jobseeker
    • Optional. When omitted, no tags are added.
    • Separate multiple tags with spaces after one t/, e.g. t/friend colleague.
    • Repeated prefixes such as t/friend t/colleague are also accepted.
    • Each tag must be alphanumeric. Duplicate tags are stored once; tags are case-sensitive.
    • An empty t/ is rejected when adding a contact. Omit it if no tags are needed.

See Common info about contacts for additional constraints on field values.

Examples:

  • addj n/John Doe p/98765432 e/johnd@example.com a/John street, block 123, #01-01 q/Diploma in IT
  • addj n/Betsy Crowe t/friend colleague e/betsycrowe@example.com a/Newgate Prison p/1234567

Adding a client: addc

Adds a client to TalentLink.

Adding duplicate client contacts is not allowed. However, adding an existing jobseeker contact to the client list is allowed

Format: addc n/<name> p/<phone number> e/<email> a/<address> [j/<job>]... [r/<remarks>] [t/<tag> [<more tags>]...]

The common contact fields follow Adding a jobseeker: addj - Format. Clients have available jobs (j/) instead of a highest qualification (q/).

  • <job>: a job title, e.g. Software Engineer. Spaces and punctuation are allowed.
  • Jobs are optional. Omit j/ to leave the list empty. Repeat j/ to list multiple jobs.
  • Repeated identical titles are stored once; titles are case-sensitive.
  • j/ alone leaves the list empty. Do not combine an empty j/ with other j/ entries.

Examples:

  • addc n/Jane Tan p/91234567 e/jane@example.com a/123 Clementi Road
  • addc n/Jane Tan p/91234567 e/jane@example.com a/123 Clementi Road j/Software Engineer j/QA Tester t/employer t/technology

Editing a jobseeker: editj

Edits an existing jobseeker in the currently displayed jobseeker list.

The command overwrites some of the jobseeker’s contact details, while leaving the rest unmodified.

Similar to addj, edits that would create duplicate jobseekers are rejected.

Format: editj <index> [n/<name>] [p/<phone number>] [e/<email>] [a/<address>] [q/<highest qualification>] [r/<remarks>] [t/<tag>]...

At least one of the fields <name>, <phone number>, <email>, <address>, <remarks>, <highest qualification>, or <tag> must be provided.

  • <index>: the index of the jobseeker to edit
    • must be a positive integer, from 1 to the size of the currently displayed jobseeker list, inclusive
  • <name>: the name of the jobseeker
  • <phone number>: the phone number of the jobseeker
  • <email>: the email address of the jobseeker
  • <address>: the address of the jobseeker
  • <highest qualification>: the jobseeker’s highest qualification
  • <remarks>: your remarks about this jobseeker
  • <tag>: a tag for this jobseeker

Notes:

  • Use q/<highest qualification> to replace the qualification, or q/ alone to clear it. Omit q/ to keep the current value. Specify q/ at most once.
  • To clear remarks, specify r/ without any values.
  • Supplied tags replace all existing tags. To clear all tags, specify t/ without any values.
  • Editing preserves hidden status and returns the view to the normal jobseeker list. An edited hidden jobseeker remains hidden.

Examples:

  • Update the first displayed jobseeker’s phone and email: editj 1 p/91234567 e/johndoe@example.com
  • Replace the second displayed jobseeker’s remark: editj 2 r/Available immediately

  • Clear the second displayed jobseeker’s remark and tags: editj 2 r/ t/

  • Replace the first displayed jobseeker’s qualification: editj 1 q/Degree in Computing
  • Clear it: editj 1 q/

Editing a client: editc

Edits an existing client in the currently displayed client list.

The command overwrites some of the client’s contact details, while leaving the rest unmodified.

Similar to addc, edits that would create duplicate clients are rejected.

Format: editc <index> [n/<name>] [p/<phone number>] [e/<email>] [a/<address>] [j/<job>]... [r/<remarks>] [t/<tag>]...

The common contact fields follow Editing a jobseeker: editj - Format. Clients accept available jobs (j/) instead of a highest qualification (q/). At least one field must be supplied; j/ alone also counts.

Notes:

  • Supplied jobs replace all existing jobs. Repeat j/ for multiple titles.
  • Use j/ alone to clear all jobs. Omit j/ to keep existing jobs.
  • Do not combine an empty j/ with other j/ entries.
  • Use r/ alone to clear remarks, and t/ alone to clear tags. Supplied tags replace all existing tags.

Examples:

  • Update the first displayed client’s remark: editc 1 r/Hiring software engineers

  • Clear that client’s remark: editc 1 r/

  • Replace the first displayed client’s jobs: editc 1 j/Software Engineer j/QA Tester
  • Clear all of that client’s jobs: editc 1 j/

Deletes a jobseeker from the currently displayed jobseeker list.

Format: deletej <index>

  • <index>: the index of the jobseeker to delete
    • must be a positive integer, from 1 to the size of the currently displayed jobseeker list, inclusive

Examples:

  • Delete the second displayed jobseeker: deletej 2

Deleting a client: deletec

Deletes a client from the currently displayed client list.

Format: deletec <index>

  • <index>: the index of the client to delete
    • must be a positive integer, from 1 to the size of the currently displayed client list, inclusive

Examples:

  • Delete the third displayed client: deletec 3

This includes contacts that aren’t listed in the currently displayed jobseeker list

Format: clearj

Clearing all clients: clearc

This includes contacts that aren’t listed in the currently displayed client list

Format: clearc

Viewing contacts

There are 2 contact lists: the jobseeker list (on the right) and the client list (on the left). Commands such as listj and listc update their respective lists independently, while list updates both lists together.

Listing jobseekers and clients: list

Shows all visible (not hidden) jobseekers and clients, and clears the current filters in both lists.

Format: list

Notes:

  • Use this command to return both lists to their normal views after searching or viewing hidden contacts.
  • Hidden contacts remain hidden. No contact details are changed.
  • To update only one list, use Listing jobseekers: listj or Listing clients: listc.

Examples:

  • listhj followed by listhc, then list, shows all visible jobseekers and clients again.
  • findj alex followed by findc roy, then list, clears both search filters.

Listing jobseekers: listj

Shows all visible (not hidden) jobseekers in the jobseeker list, and clears the current jobseeker filter.

For more information on hidden jobseekers, see Hiding a jobseeker: hidej.

To list hidden jobseekers, see Listing hidden jobseekers: listhj.

Format: listj

Listing clients: listc

Shows all visible (not hidden) clients in the client list, and clears the current client filter.

For more information on hidden clients, see Hiding a client: hidec.

To list hidden clients, see Listing hidden clients: listhc.

Format: listc

Finding jobseekers: findj

Finds jobseekers whose name, phone number, email or tags contain any of the given keywords.

The search is case-insensitive and is inclusive, as in:

  • inputting hans or Hans both matches Hans Gruber
  • inputting Hans Bo matches both Hans Gruber and Bo Yang.

For more information on hidden jobseekers, see Hiding a jobseekers: hidej.

To search among hidden jobseekers, see Finding hidden jobseekers: findhj.

Format: findj <keyword>...

  • <keyword>: a keyword to search for
    • At least one keyword must be given.

Notes:

  • Partial words match.

    For example, Han matches Hans, and 9435 matches the phone number 94351253.

  • Keyword order does not matter.

    For example, Hans Bo is equivalent to Bo Hans.

  • Only the name, phone number, email and tags are searched. Addresses and remarks are not.

  • Each keyword must match within a single field.

    For example, Yeoh8743 does not match a jobseeker named Alex Yeoh whose phone number is 87438807.

Examples:

  • findj alex david returns Alex Yeoh and David Li.
  • findj li returns Charlotte Oliveiro and David Li, since li appears inside both names.
  • findj 9103 returns David Li, whose phone number is 91031282.
  • findj friends returns Alex Yeoh and Bernice Yu, who are both tagged friends.

Finding clients: findc

Finds clients whose name, phone number, email or tags contain any of the given keywords.

The search is case-insensitive and is inclusive.

For more information on hidden clients, see Hiding a client: hidec.

To search among hidden clients, see Finding hidden clients: findhc.

Format: findc <keyword>...

  • <keyword>: a keyword to search for
    • At least one keyword must be given.

Notes:

The notes are the same as findj. See Finding jobseekers: findj - Notes.

Examples:

  • findc roy returns Roy Balakrishnan.
  • findc irfan@example.com returns Irfan Ibrahim.
  • findc colleagues returns Roy Balakrishnan, who is tagged colleagues.

Finding jobseekers and clients: find

Finds jobseekers and clients whose name, phone number, email or tags contain any of the given keywords.

This does the same as running findj and findc with the same keywords, so both lists are filtered at once. This is useful for finding every contact with a certain tag, such as an industry.

Hidden jobseekers and clients are not searched.

Format: find <keyword>...

  • <keyword>: a keyword to search for
    • At least one keyword must be given.

Notes:

The notes are the same as findj. See Finding jobseekers: findj - Notes.

Examples:

  • find colleagues returns the jobseeker Bernice Yu and the client Roy Balakrishnan, who are both tagged colleagues.
  • find alex roy returns the jobseeker Alex Yeoh and the client Roy Balakrishnan.

Hiding a jobseeker: hidej

Hides the specified jobseeker, so that listj and findj no longer show them.

Unlike deleting, hiding keeps the jobseeker and all their details in TalentLink.

To list hidden jobseekers, see Listing hidden jobseekers: listhj.

To search among hidden jobseekers, see Finding hidden jobseekers: findhj.

Format: hidej <index>

  • <index>: the index of the jobseeker to hide
    • must be a positive integer, from 1 to the size of the currently displayed jobseeker list, inclusive

Examples:

  • listj followed by hidej 2 hides the 2nd jobseeker in the jobseeker list.
  • findj Betsy followed by hidej 1 hides the 1st jobseeker in the results of the findj command.

Hiding a client: hidec

Hides the specified client, so that listc and findc no longer show them.

Unlike deleting, hiding keeps the client and all their details in TalentLink.

To list hidden clients, see Listing hidden clients: listhc.

To search among hidden clients, see Finding hidden clients: findhc.

Format: hidec <index>

  • <index>: the index of the client to hide
    • must be a positive integer, from 1 to the size of the currently displayed client list, inclusive

Examples:

  • listc followed by hidec 1 hides the 1st client in the client list.

Unhiding a jobseeker: unhidej

Make a hidden jobseeker visible to listj and findj again.

This command must be used while listhj or findhj is in effect.

For more information on hidden jobseekers, see Hiding a jobseeker: hidej.

Format: unhidej <index>

  • <index>: the index of the jobseeker to unhide
    • must be a positive integer, from 1 to the size of the currently displayed jobseeker list, inclusive

Examples:

  • listhj followed by unhidej 1 restores the first displayed hidden jobseeker.

Unhiding a client: unhidec

Make a hidden client visible to listc and findc again.

This command must be used while listhc or findhc is in effect.

For more information on hidden clients, see Hiding a client: hidec.

Format: unhidec <index>

  • <index>: the index of the client to unhide
    • must be a positive integer, from 1 to the size of the currently displayed client list, inclusive

Examples:

  • listhc followed by unhidec 1 restores the first displayed hidden client.

Listing hidden jobseekers: listhj

Shows all hidden jobseekers in the jobseeker list, and clears the current jobseeker filter.

For more information on hidden jobseekers, see Hiding a jobseeker: hidej.

Format: listhj

To return both lists to their visible contacts, use Listing jobseekers and clients: list.

Listing hidden clients: listhc

Shows all hidden clients in the client list, and clears the current clients filter.

For more information on hidden clients, see Hiding a client: hidec.

Format: listhc

To return both lists to their visible contacts, use Listing jobseekers and clients: list.

Finding hidden jobseekers: findhj

Finds hidden jobseekers whose name, phone number, email or tags contain any of the given keywords.

The search logic is the same as findj. See Finding jobseekers: findj for more details.

Format: findhj <keyword>...

  • <keyword>: a keyword to search for
    • At least one keyword must be given.

Examples:

  • findhj alex returns Alex Yeoh, if Alex Yeoh has been hidden.

Finding hidden clients: findhc

Finds hidden clients whose name, phone number, email or tags contain any of the given keywords.

The search logic is the same as findc. See Finding clients: findc for more details.

Format: findhc <keyword>...

  • <keyword>: a keyword to search for
    • At least one keyword must be given.

Examples:

  • findhc irfan returns Irfan Ibrahim, if Irfan Ibrahim has been hidden.

Managing Tags

Tags are labels with arbitrary names that you can put on jobseekers and clients. They can be used to help you organize contacts and speed up searches.

Tags contains the following attributes, and their corresponding constraints:

  • Name
    • must contain only alphanumeric characters
    • is case-sensitive, unlike the parameters to findj and findc

Tags are identified by their names, i.e. 2 tags with the same name, case-sensitive, are considered the same tags.

A jobseeker or client contact can have multiple tags, or no tags at all.

Adding jobseeker tags: tagj

Adds tags to a jobseeker while preserving existing tags.

Format: tagj <index> <tag>...

  • <index>: the index of the jobseeker to add the tag to
    • must be a positive integer, from 1 to the size of the currently displayed jobseeker list, inclusive
  • <tag>: the name of a tag to add
    • At least one tag name must be given.

Examples:

  • tagj 1 java adds java to the 1st displayed jobseeker.
  • tagj 2 python teamwork adds python and teamwork to the 2nd displayed jobseeker.

Adding client tags: tagc

Adds tags to a client while preserving existing tags.

Format: tagc <index> <tag>...

  • <index>: the index of the client to add the tag to
    • must be a positive integer, from 1 to the size of the currently displayed client list, inclusive
  • <tag>: the name of a tag to add
    • At least one tag name must be given.

Examples:

  • tagc 1 priority adds priority to the 1st displayed client.
  • tagc 2 finance technology adds finance and technology to the 2nd displayed client.

Removing jobseeker tags: untagj

Removes specified tags from a jobseeker while preserving other tags.

Format: untagj <index> <tag>...

  • <index>: the index of the jobseeker to remove the tag from
    • must be a positive integer, from 1 to the size of the currently displayed jobseeker list, inclusive
    • <tag>: the name of a tag to add
      • At least one tag name must be given.

Examples:

  • untagj 1 java removes java from the 1st displayed jobseeker.
  • untagj 2 python teamwork removes python and teamwork from the 2nd displayed jobseeker.

Removing client tags: untagc

Removes specified tags from a client while preserving other tags.

Format: untagc <index> <tag>...

  • <index>: the index of the client to remove the tag from
    • must be a positive integer, from 1 to the size of the currently displayed client list, inclusive
  • <tag>: the name of a tag to add
    • At least one tag name must be given.

Examples:

  • untagc 1 priority removes priority from the 1st displayed client.
  • untagc 2 finance technology removes finance and technology from the 2nd displayed client.

Miscellaneous commands

Copying displayed jobseekers: cpj

Copies the details of all currently displayed jobseekers to the system clipboard.

Format: cpj

Notes:

  • The copied details follow the order shown in the jobseeker list.
  • Each jobseeker is copied on a separate line.
  • The command only copies whichever jobseekers are currently displayed. If no jobseekers are displayed, the clipboard is cleared.

Examples:

  • findj java followed by cpj copies the displayed search results.

Copying displayed clients: cpc

Copies the details of all currently displayed clients to the system clipboard.

Format: cpc

Notes:

The notes are the same as cpj. See Copying displayed jobseekers: cpj - Notes for notes.

Examples:

  • findc technology followed by cpc copies the displayed search results.

Saving the data

TalentLink automatically saves data after every command. You do not need to save manually.

Revisit past commands

Use the up and down arrow keys to revisit commands from your command history.

Autocomplete commands

Type part of a command (e.g. list) to see suggestions. Use Up/Down to select one, then Tab or Enter to complete it. Press Enter again to run the command, or Escape to dismiss suggestions.

Editing the data file

TalentLink data is saved automatically as a JSON file [JAR file location]/data/addressbook.json. Advanced users are welcome to update data directly by editing that data file.

Caution: If your changes make the data file invalid, TalentLink starts with empty jobseeker and client lists at the next run. The invalid file remains on disk until you run a command (TalentLink saves after every command). Still, we recommend backing up the file before editing it. Furthermore, certain edits can cause TalentLink to behave in unexpected ways (e.g., if a value entered is outside the acceptable range). Therefore, edit the data file only if you are confident that you can update it correctly.

FAQ

Q: How do I transfer my data to another computer?
A: Install the app on the other computer and overwrite the data file it creates with the data file from your previous TalentLink home folder.

Known issues

  1. When using multiple screens, if you move the application to a secondary screen, and later switch to using only the primary screen, the GUI will open off-screen. The remedy is to delete the preferences.json file created by the application before running the application again.
  2. If you minimize the Help Window and then run the help command (or use the Help menu, or the keyboard shortcut F1) again, the original Help Window will remain minimized, and no new Help Window will appear. The remedy is to manually restore the minimized Help Window.
